# Native race export

`races.write(out, city, catalog_paths=None, opponent_vehicle_geo="sthlm_racer")` emits the Checkpoint, Blitz and Circuit tables present in `config/races`. Optional explicit paths support isolated authoring. The return value and `races.json` record exact source edges, owning ways, road-width bottlenecks, dense engine-coordinate paths, sparse marker positions, source-safe grids and variant guide paths. Hook this after original vehicle generation and before package checksum generation.

`source_graph(city)` clips every retained source segment to `city["bounds"]` with one centimetre numerical tolerance. `resolve_anchor(city, anchor, graph=None)` rejects missing node/way ownership; heights come from the owning road's elevated profile. `route(city, anchors, closed=False, graph=None)` performs deterministic shortest routing through true shared nodes, emitting `{nodes, points, edges, way_ids, length_m, minimum_width_m, closed}`. `points` are engine east/up/south metres; source geometry stays east/north. Exact source segment stations handle closed OSM ways whose start node repeats, without wrapping an edge onto the wrong part of its profile. Incompatible height joins fail closed.

Gameplay markers remain sparse. Trigger radius covers road half-width plus four metres of normal passing clearance, bounded to 6–15 m. Exact owning-source road height remains unchanged. Overlapping native gate footprints are rejected before export. Native AnyOrder CSVs contain START, unordered gates, FINISH; Circuit CSVs contain START and ordered gates, with the native engine closing through START. `route_via` is a separate full driving itinerary, never extra gameplay gates. Every visible gate must lie on the driving guide. Alternative Checkpoint `opponent_orders` cycle legal gate permutations among AI paths. Native `_strtpnts` stage the player on the authored line and AI cars in single file every eight metres behind it, walking actual connected source roads and sampling their profiles. No lateral or water shortcuts are invented.

Amateur/Professional parameter blocks are written verbatim. Only Blitz `TimeLimit` binds a countdown; other modes have elapsed time. Raw `Difficulty` is a native table field, separate from selecting a difficulty block. `target_speed_mps` is an authored tuning goal exported in path metadata; its column semantics in the fan engine are not asserted as a controlling speed. The ten-value AIMAP driving tail follows the documented RACE-14 order: throttle ceiling, unused flag, look-ahead, brake floor, traffic/prop/player/opponent avoidance flags, unusual-pathfinding flag, corner-speed multiplier. Player/AI avoidance is enabled and corner speed is explicitly positive; a zero-filled tail would disable avoidance and make the current engine brake every turn to zero. Amateur/Professional throttle is 0.65/0.85 and corner multiplier 0.9/1.05, requiring native tuning evidence. Actual physical competition needs the original `sthlm_racer` vehicle generated by `race_vehicle.write`, or another explicitly selected legitimate vehicle.

Every mode also emits `qa/races/<stem>-a-guide.opp` and `-p-guide.opp` outside the native catalog. The generic engine evidence driver can consume these through explicit `--bot-route PATH`; Blitz remains a zero-opponent mode. An empty `mmcrashdata.csv` header supplies a complete zero-lesson school when no school is authored; no Crash Course events are invented. QA guides are outside `race/stockholm`, so strict event inspection reports no orphan opponent routes.

Native gate planes use each exact owning road’s local tangent. Their normal convention is X = −sin(a), Z = +cos(a), distinct from vehicle spawn yaw (Z = −cos(a)); a shared grid heading must never orient every gameplay gate.
